# Centralized Errors Log

## Purpose

This file is the single auditable register for repo-level error checks, failed
validations, unresolved implementation gaps, and verification blockers.

Use it to consolidate scattered checks from implementation plans, test runs, and
manual audits into one place. Each entry must be traceable to a specific source,
file path, command, or observed output. Do not record assumptions as errors.

---

## Status Legend

| Status | Meaning |
|---|---|
| OPEN | Verified issue exists and still needs action |
| BLOCKED | Verification or remediation is blocked by environment, data, or access |
| WATCH | Not a confirmed defect, but needs follow-up validation |
| CLOSED | Verified resolved with evidence |

---

## Entry Format

| ID | Status | Area | Error Check | Evidence | Required Action | Verification |
|---|---|---|---|---|---|---|
| ERR-000 | TEMPLATE | area/module | Exact failure or invariant being checked | File:line, command output, or artifact evidence | Minimal corrective action | Command or audit step that proves closure |

## Audit Rules

1. Record only verified errors, failed checks, or explicitly blocked validations.
2. Every active entry must include evidence and a verification path.
3. Do not add speculative model-risk claims without a file path, command output,
   artifact diff, or reproducible validation result.
4. Prefer minimal corrective actions. Do not introduce optional fallbacks unless
   the architecture requires them and the requirement is documented.
5. When an issue is fixed, move it to `Closed Error Checks` with the exact proof
   used to close it.
