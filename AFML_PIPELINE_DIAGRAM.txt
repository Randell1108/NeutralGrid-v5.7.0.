         │  compute_concurrency_matrix(t0, t1)     │
         │  ───────────────────────────────────    │
         │  For each event i:                      │
         │    1. Count overlapping events j        │
         │       overlap[i,j] = (t0[i]≤t1[j]) AND  │
         │                       (t0[j]≤t1[i])     │
         │    2. concurrency[i] = sum(overlap[i,:])│
         └──────────────────┬──────────────────────┘
                            │
                            ▼
         ┌─────────────────────────────────────────┐
         │  compute_uniqueness_weights(t0, t1)     │
         │  ───────────────────────────────────    │
         │  weight[i] = 1.0 / concurrency[i]       │
         │                                         │
         │  Normalize: weights *= N / sum(weights) │
         └──────────────────┬──────────────────────┘

         │  ───────────────────────────────────    │

         │  weight[i] *= exp(-ln(2)*age/halflife)  │
         └──────────────────┬──────────────────────┘

                             KEY DESIGN PRINCIPLES
════════════════════════════════════════════════════════════════════════════════

1. SINGLE SOURCE OF TRUTH
   ├─ compute_hmm_features() used in both training and inference
   ├─ No code duplication between pipelines
   └─ Training-serving alignment guaranteed

2. TIME-BASED PURGING
   ├─ Uses event horizons [t0, t1], not indices
   ├─ Prevents information leakage across CV folds
   └─ Embargo period protects against forward contamination

3. CV-AWARE IMPUTATION
   ├─ Imputer fit on train fold only
   ├─ Same imputer used in inference
   └─ No look-ahead bias from missing value handling

4. SAMPLE WEIGHTING
   ├─ Corrects for overlapping event concurrency
   ├─ Events in crowded regimes get lower weight
   └─ Prevents over-representation of specific market conditions

5. PROBABILITY CALIBRATION
   ├─ Isotonic regression for reliable probability estimates
   ├─ Meta-model outputs P(success), not just scores
   └─ Enables proper decision-making under uncertainty

6. TRUE HOLDOUT
   ├─ 20% most recent data reserved
   ├─ NEVER used during CV or model selection
   └─ Station 4 compliance for final evaluation

7. DETERMINISTIC TRAINING
   ├─ random_state=42 for reproducibility
   ├─ Same data always produces same model
   └─ Facilitates debugging and auditing

8. REALISTIC BACKTESTING
   ├─ Close-to-close execution (matches Binance grid bot behavior)
   ├─ Resting limit orders fill on touch (no artificial cooldowns)
   └─ Validated against live trading results
